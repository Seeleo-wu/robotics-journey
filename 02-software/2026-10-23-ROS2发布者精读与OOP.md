## 一、OOP 四件事（今天补上的）

| 概念 | 一句话 | 在代码里对应 |
|---|---|---|
| **类 = 模具** | 一段描述，本身不干活 | `class Spinner(Node):` |
| **实例 = 用模具压出来的东西** | 真正在跑的那个 | `node = Spinner()` |
| **`__init__` = 出厂设置** | 创建实例时自动跑一次 | `super().__init__('spinner')` 等 4 行 |
| **`self` = 这个具体的个体** | 「我自己」 | `self.pub` / `self.n` |

**关键时序：写 `class Spinner` 那一段代码时，里面的代码一行都不执行。**
只有执行到 `Spinner()` 的那一刻，`__init__` 才跑起来。

## 二、继承 ≠ 定义（今天纠正的第一个错误）

**`create_publisher` 定义在 Node 里，不在 Spinner 里。**

```
Spinner 能「用」它  ≠  它「定义」在 Spinner 里
类比：你会用家里的洗衣机，不代表洗衣机是你造的
```

**验证命令（一条判决书）**

```bash
python3 -c "
from rclpy.node import Node
class Spinner(Node): pass
print('在 Spinner 里:', 'create_publisher' in Spinner.__dict__)
print('在 Node 里:   ', 'create_publisher' in Node.__dict__)
"
```

**输出：**

```
在 Spinner 里: False
在 Node 里:    True
```

**`dir()` 与 `__dict__` 的区别就是继承的本质：**

| 写法 | 列出什么 |
|---|---|
| `dir(类)` | 这个类「能用到的」全部，**含继承来的** |
| `类.__dict__` | 只列这个类**自己定义的** |

**`super().__init__('spinner')` 为什么必须写：**

```
Node 的 __init__ 里做的事：
  向 ROS2 系统注册这个节点
  建立和底层通信层的连接
  初始化日志、参数、时钟等基础设施

不写它 → 节点是个「没上牌照的车」→ 后面 create_publisher 会直接报错
```

## 三、Node 给了什么

**先说一个区分：Node 给的主要是「方法」（能力），不是「属性」（数据）。**

| | 是什么 | 例子 |
|---|---|---|
| **属性** attribute | **数据** | `self.n = 0`、自己的 `self.pub` |
| **方法** method | **能力**（函数） | `create_publisher(...)` |

**Node 的常用方法（分四类）**

| 类别 | 方法 | 干什么 |
|---|---|---|
| 创建 | `create_publisher(类型, 话题, 队列)` | 建发布者 |
| 创建 | `create_subscription(类型, 话题, 回调, 队列)` | 建订阅者 |
| 创建 | `create_timer(秒, 回调)` | 建定时器 |
| 创建 | `create_service / create_client` | 服务端 / 客户端 |
| 创建 | `create_rate(频率)` | 节拍器 |
| 信息 | `get_name() / get_namespace() / get_fully_qualified_name()` | 节点名、命名空间、全名 |
| 信息 | `get_logger()` | 日志器（`.info() .warn() .error()`） |
| 信息 | `get_clock()` | 时钟 |
| 参数 | `declare_parameter / get_parameter / set_parameters` | 可外部配置的参数 |
| 销毁 | `destroy_publisher / destroy_subscription / destroy_timer` | 单独销毁 |
| 销毁 | `destroy_node()` | 销毁整个节点 |

**不要背这张表——自己查（ROS2 版本之间有差异）**

```bash
# 看 Node 有多少公开方法
python3 -c "from rclpy.node import Node; print(len([m for m in dir(Node) if not m.startswith('_')]))"

# 看构造器的完整参数
python3 -c "from rclpy.node import Node; help(Node.__init__)"

# 看某个方法的完整签名
python3 -c "from rclpy.node import Node; help(Node.create_subscription)"
```

**`help()` 是 Python 自带的，任何库都能查。**
遇到不认识的库，第一反应应该是 `help()`，不是搜网页。

## 四、运行时的真相：事件循环与回调

**这是今天最有价值的一块。**

```
rclpy.spin(node)

→ 程序进入「事件循环」，ROS2 底层反复做三件事：
    检查有没有定时器到时间 → 到了就调 tick()
    检查有没有订阅的消息到 → 到了就调回调
    检查有没有服务请求     → 有就调服务回调
```

**几个必须分清的细节：**

| 说法 | 对不对 | 正确说法 |
|---|---|---|
| spin 是「死循环」 | ❌ | **事件循环**。死循环占满 CPU；事件循环在等事件，随时响应 |
| spin 每一轮都调 tick | ❌ | spin 一秒转几千次，但 tick 只在距上次超过 **0.1 秒**时才被调 |
| 我写的代码调用了 tick | ❌ | **没有任何一行调用它**。`create_timer(0.1, self.tick)` 只是把函数交出去 |
| 删掉 spin 程序会崩 | ❌ | 不会崩，是**跑完就立刻退出**。`tick` 一次都不会被调 |

**回调的本质（今天想通了）：**

| 写法 | 含义 |
|---|---|
| `self.create_timer(0.1, self.tick)` | 把**函数本身**交出去，**不带括号** |
| `self.create_timer(0.1, self.tick())` | **立刻调用**，把返回值（None）交出去 → 报错 |

**记忆法：写回调时问自己「我是要把这件事交给别人，还是要现在就做？」**
**要交出去 → 不带括号。**

**控制反转（IoC）：控制权在 ROS2 手里，它决定什么时候调用你的函数。**

## 五、turtle_spin.py 逐行「运行时」注释

这一节只写**运行时到底发生了什么**，语法见上一份笔记。

| 代码 | 运行时发生了什么 |
|---|---|
| `import rclpy` 等三行 | 去磁盘加载三个模块。**不涉及任何 ROS2 通信** |
| `class Spinner(Node):` | 建立类对象，把 Node 的方法挂上。**不执行 `__init__` 里的代码** |
| `node = Spinner()` | **触发 `__init__` 全部执行** |
| `super().__init__('spinner')` | 跳到 Node 的构造器，**ROS2 底层真正确立这个节点**。执行完这行，`ros2 node list` 就能看到 `/spinner` |
| `self.pub = self.create_publisher(...)` | 右边是**父类能力**，左边是**自己的属性**。这一行就是「继承 + 自我扩展」的样板 |
| `self.n = 0` | 纯粹的自己的属性，与 ROS2 无关。**整个程序只执行 1 次** |
| `def tick(self):` | **不执行**，只是给这个个体加一个能力 |
| `self.pub.publish(msg)` | 走自己身上的 pub → 调它的 publish → **底层序列化并广播到话题上** |
| `rclpy.init()` | 初始化 ROS2 通信系统（不是节点）。**必须在建节点之前** |
| `rclpy.spin(node)` | **阻塞**，进入事件循环 |
| `node.destroy_node()` | 撤销所有发布者/订阅者/定时器 |
| `if __name__ == '__main__':` | 直接运行时 `__name__` 是 `'__main__'`；被 import 时是文件名 |

**顺序不能反：先 destroy_node，再 shutdown。**

## 六、11 题测验：摸到的三个真实缺口

**测验结果**

| 档位 | 题号 | 结果 |
|---|---|---|
| 概念 | 1 2 3 4 | 对 2（事件循环、回调）、错 2（继承方向、__init__ 次数） |
| 预测 | 5 6 7 | 对 1、半对 2（术语错） |
| 找 bug | 8 9 | 半对 1、未答 1 |
| 开放 | 10 11 | 术语错 + 未动手、对 |

**缺口一：继承 vs 定义**

```
错答：create_publisher 定义在 Spinner 里（因为 Spinner 继承了 Node）
正确：定义在 Node 里，Spinner 只是「能用」
验证：'create_publisher' in Spinner.__dict__  →  False
```

**缺口二：__init__ 的执行次数**

```
错答：self.n = 0 执行 24 次
正确：1 次（在 Spinner() 那一刻）
混淆源：self.n += 1 才是每次 tick 执行，2.4 秒 ≈ 24 次

记忆法：__init__ 是「出厂设置」只跑一次；方法是「日常干活」跑很多次
```

**缺口三：术语（口误，但值得摆正）**

| 名词 | 符号 | 单位 | 代码里是哪个 |
|---|---|---|---|
| **角速度** angular velocity | ω | rad/s | **`msg.angular.z` = 1.8** |
| 角加速度 | α = dω/dt | rad/s² | 没有 |
| **法向（向心）加速度** | aₙ = v²/r = v·ω | 单位/s² | **= 2.0 × 1.8 = 3.6** |

**所以「法向加速度是 1.8」是错的，那个数是 3.6。**
机械专业的人在面试/考试说错这个，会被直接判为没学懂理论力学。
